# 多平台 CDK 售卖库存查询工具

一个面向 CDK 卡商（卖家）的**桌面库存查询小工具**：在一个窗口里对接
**STEAMCICI** 与 **SteamPY** 两个平台，读取并展示「我自己」的挂售库存，
支持两张表格展示与一键导出 Excel / CSV。

双击即用、无需联网安装依赖、不写注册表、不留后台进程。

## 项目简介

在 STEAMCICI 与 SteamPY 上卖 CDK 时，想盘点库存通常要开两个网站、来回登录、手动翻页，
还容易被网页上的「全市场挂单」干扰，看不清哪些是**自己的**货。

本工具解决的就是这个问题：

- **一个窗口看两个平台**，下拉切换即可；
- **只读取你自己账号的数据**（SteamPY 侧刻意使用 `listSelf` 而非全市场的 `listSale`）；
- 把数据整理成两张表：**游戏维度**的库存汇总 + **挂单维度**的明细；
- 一键导出成**真正的两张工作表**的 Excel 文件，方便对账、统计、存档。

> 本项目是个人自用工具的通用化版本，**与 STEAMCICI、SteamPY 官方均无关联**。

## 核心功能与特色

### 双平台一站式

顶部下拉框即可在 **STEAMCICI** 与 **SteamPY** 之间切换。切换时自动读取该平台已保存的
凭证并重新查询，两张表格的列定义、表名、状态映射都会跟着平台变化。

### 只取「我自己的」数据

这是本工具与「直接抓网页」最大的区别：

| 平台 | 数据来源 | 说明 |
|---|---|---|
| STEAMCICI | `/user/system/shopSell/list`、`.../queryStock` | 用户级接口，仅返回本人挂售 |
| SteamPY | `/{区}/listGame`、`/{区}/listSelf` | **刻意避开 `listSale`**（那是全市场挂单列表，会把别人的挂单和价格一起带回来） |

SteamPY 的国区 / 全球区 / 俄罗斯区会分别拉取后合并，明细表带「分区」列便于区分。

### 两张表，各司其职

| 表 | 粒度 | 用途 |
|---|---|---|
| **游戏库存** | 每个挂售游戏一行 | 看哪些游戏在卖、各剩多少货 |
| **CDK 明细 / 挂售明细** | 每条挂单一行 | 看单条挂单的价格、状态、时间 |

### 默认排序（开箱即用）

- **游戏库存**：按「当前库存」**降序**，缺货游戏自动沉底
- **SteamPY 挂售明细**：按「库存」**降序**
- **STEAMCICI 明细**：按状态优先级排序，**未出库的排在前面、已售出的往后排**

排序在填表前完成，因此**屏幕上的顺序与导出文件里的顺序完全一致**。

### 导出：真正的工作簿

- **`.xlsx`（默认）**：文件内是**两张独立工作表**，各占一个页签，互不混合
- **`.csv`（可选）**：单文件内上下两块表，中间以空行分隔

导出时自动带上时间戳文件名，编码为 `utf-8-sig`，Excel 打开中文不乱码。

### 零第三方依赖

整个程序**只用 Python 标准库**，其中 `.xlsx` 是**用 `zipfile` 手写 OOXML** 生成的——
所以不需要 `pip install openpyxl`，拷到任何装了 Python 的电脑上都能直接跑。

### 面向真实使用场景的稳健性

- 网络请求**自动重试 3 次**（指数退避），支持分页自动拉全
- 请求间隔节流，避免触发平台风控
- 查询跑在**后台线程**，界面不卡死，状态栏实时汇报进度
- **401 自动识别**：凭证失效时弹窗并自动打开更换凭证对话框
- **明细接口失败自动降级**：只跳过明细，汇总照常显示
- **明细自动去重**：按「分区 + 挂单 ID」去重，防止分页重叠重复计数
- **翻页硬上限**：防止接口异常时无限刷请求

## 安装与使用

### 1. 准备 Python

```bash
python --version      # 确认是 Python 3.8+
python -c "import tkinter; print('tkinter OK')"
```

若第二步报错，请到 [python.org](https://www.python.org/downloads/) 重新安装官方版，
安装时勾选 `tcl/tk and IDLE`。

### 2. 放置文件

把 `steamcici查询.pyw` 放到任意目录（**建议单独建一个文件夹**，配置会生成在同目录）。

> `.pyw` 后缀表示用 `pythonw` 运行，**不会弹出黑色命令行窗口**。

### 3. 双击运行

双击 `steamcici查询.pyw` 即可打开窗口。

首次运行时会自动弹出凭证设置对话框，粘贴对应平台的凭证后点「保存并查询」。

### 4. 日常使用

1. 顶部下拉框选择平台（记忆上次选择）
2. 点左侧绿色的 **「查询」** 按钮
3. 查看两张表：**游戏库存** / **挂售明细**
4. 需要存档时点 **「导出表格」**

| 按钮 | 作用 |
|---|---|
| 查询 | 重新拉取当前平台的数据 |
| 导出表格 | 导出为 `.xlsx`（默认，两张工作表）或 `.csv` |
| 更换凭证 | 凭证过期或换账号时重新填写 |

> 已有凭证时，程序启动会自动查询一次，无需手动点。

## 凭证获取方法

两个平台的凭证都是**账号级凭据**，等价于你的登录身份，**请勿外传**。

### STEAMCICI —— `Admin-Token`

1. 浏览器登录 [steamcici.com](https://steamcici.com)
2. 按 `F12` 打开开发者工具，切到「控制台 / Console」
3. 粘贴下面这行并回车，凭证会自动复制到剪贴板：

```js
copy(document.cookie.split('; ').find(r=>r.startsWith('Admin-Token=')).split('=').slice(1).join('='))
```

### SteamPY —— `accessToken`

1. 浏览器登录 [steampy.com](https://steampy.com)（需登录**卖家账号**）
2. 按 `F12`，切到「控制台 / Console」
3. 粘贴下面这行并回车：

```js
copy(localStorage.getItem('accessToken') || '没找到，请确认已登录')
```

> 注意：SteamPY 的凭证存在 **localStorage**（不是 Cookie）。
> 也可以在 `F12` → 「Application / 应用」→「Storage → Local Storage」→
> `https://steampy.com` → 找到 `accessToken` 这一项手动复制。

### 关于「复制不到」的两个正常现象

| 现象 | 说明与处理 |
|---|---|
| 提示 `Warning: Don't paste code into the DevTools Console...` | 浏览器的防诈骗保护，**不是报错**。在控制台输入框里手动输入 **`允许粘贴`** 并回车，然后再粘贴一次即可 |
| 粘贴执行后回显 `undefined` | **这是成功信号**。`copy()` 只负责写入剪贴板、本身没有返回值。此时凭证已在剪贴板里，可直接粘贴到工具中（可先粘到记事本确认是一串长字符） |

## 配置说明

配置文件为程序同目录下的 **`steamcici_config.json`**，首次保存凭证时自动生成：

```json
{
  "token": "<STEAMCICI 的 Admin-Token>",
  "steampy_token": "<SteamPY 的 accessToken>",
  "last_platform": "steamcici"
}
```

| 键 | 含义 | 备注 |
|---|---|---|
| `token` | STEAMCICI 凭证 | 沿用旧版的键名，**老配置文件可直接使用** |
| `steampy_token` | SteamPY 凭证 | 各平台各存各的，互不覆盖 |
| `last_platform` | 上次使用的平台 | `steamcici` 或 `steampy`，用于下次启动时默认选中 |

**说明：**

- 两个平台的凭证分别保存，切换平台不会互相覆盖
- 配置文件缺失、损坏或格式错误时，程序会静默降级为「没有凭证」并弹出设置窗口，不会崩溃
- 更换凭证时是整体重写该文件（`indent=2`，UTF-8）

> **安全警告**：该文件以**明文**保存凭证。分享项目、提交代码仓库、发截图前，
> 请务必删除或清空该文件。建议在仓库中添加 `.gitignore` 并写入
> `steamcici_config.json`。

## 导出说明

### `.xlsx`（推荐）

单个工作簿，内含**两张独立工作表**：

| 平台 | 工作表 1 | 工作表 2 |
|---|---|---|
| STEAMCICI | 游戏库存 | CDK 明细 |
| SteamPY | 游戏库存 | 挂售明细 |

**字段设计上的两个细节：**

- 「当前库存」「库存总数」/「库存」等数量字段写成**数字**，可直接在 Excel 里求和；
- 其余字段（长 ID、价格等）一律写成**文本**，避免长 ID 被显示成科学计数法、
  避免 `12.50` 这类价格被抹掉末尾的 `0`。

### `.csv`（可选）

在保存对话框里把类型改成 CSV 即可。CSV 格式本身不支持多工作表，因此两张表会
**上下排列在同一文件内，以一个空行分隔**：

```
游戏库存
<表头>
<数据行...>

挂售明细
<表头>
<数据行...>
```

## 目录结构

```
cdk sale/
├── steamcici查询.pyw          # 主程序，唯一入口，双击即可运行
├── steamcici_config.json      # 凭证与偏好设置（首次运行生成，含敏感信息）
└── 导出示例_两张工作表.xlsx    # 导出效果示例（内容为虚构数据，可删除）
```

程序内部按「平台注册表」组织，新增平台只需再注册一个 `Platform` 对象：

```
常量与通用网络层
  ├─ _get_json()      底层 GET + 重试 + JSON 解析
  ├─ _paged()         通用分页（翻页参数名可配置）
  └─ 工具函数         _to_int / _map / _clean_time / _min_price / _breakdown / 排序
平台一：STEAMCICI      sc_fetch / sc_collect / SELL_STATUS / STOCK_STATUS ...
平台二：SteamPY        py_fetch / py_collect / PY_REGIONS / PY_SALE_STATUS ...
平台注册表             Platform 类 + PLATFORMS + PLATFORM_ORDER
配置与凭证对话框       load_config / save_token / TokenDialog
导出                  export_blocks（CSV）/ create_xlsx + export_excel（XLSX）
主窗口                App（平台下拉 / 两张表 / 后台查询 / 导出）
```

## 常见问题

**Q：双击没反应，或者弹出「启动失败」？**
A：多半是缺少 `tkinter`。用命令行运行 `python steamcici查询.pyw` 可以看到具体报错。

**Q：提示「认证失败(401)」？**
A：凭证过期或已失效。点「更换凭证」重新获取（换设备登录、退出登录都会导致旧凭证失效）。

**Q：SteamPY 一条数据都查不到？**
A：确认登录的是**卖家账号**；另外该账号在对应分区需确实有挂单。

**Q：游戏库存表里有些列为空？**
A：两个平台提供的字段不完全相同。例如 STEAMCICI 的「最低售价」、SteamPY 的
「最低售价」分别来自各自平台的字段，平台没提供时即为空。

**Q：导出的 xlsx 提示「文件需要修复」？**
A：本项目的 xlsx 是手写 OOXML 生成的，已针对 Excel / WPS 做过兼容性校验
（含完整样式表）。若仍出现，请附上报错截图提 issue。

**Q：查询很慢？**
A：查询会逐个分区拉取并自动翻页，数据量大时耗时较长。状态栏会实时显示进度，
界面不会卡死，请耐心等待。

1. **凭证即身份**。`Admin-Token` 与 `accessToken` 都是账号级凭据，泄露后他人可以
   以你的身份读取（甚至操作）你的挂售数据。请勿截图、外传或提交到代码仓库。
2. **配置文件明文存储**。`steamcici_config.json` 未做加密，共享项目前请先清空。
3. **非官方工具**。本项目与 STEAMCICI、SteamPY 官方无任何关联，也未获得其授权或认可。
4. **请遵守平台条款**。本工具仅用于查询**自己账号**的数据，请勿用于批量抓取、
   爬取他人数据或其他违反平台服务条款的用途。
5. 程序不会上传任何数据到第三方服务器，所有数据仅在你的电脑与对应平台之间传输。

## 已知限制

- SteamPY 没有提供账号昵称接口，该平台查询后信息栏的账号位显示为 `—`
